## Why

`FE-R07` 讓畫面上出現了別人 —— **但他們不會動**，因為我們沒有把自己的位置送出去。
兩個分頁互看的時候，雙方都只看得到一個站在原點的角色。

W1 里程碑那一列的「看得到別人」現在只成立了一半。

**不做會發生的具體事情**：下一個要送位置的人會在 `LocalPlayer` 的 `useFrame`
裡直接 `client.send(...)`。那有三個後果，每一個的失敗都是無聲的：

1. **每秒送 60 次。** 後端 `HZ = 10`，多送的 50 次全部浪費，
   而且後端**沒有 rate limit**（`BE-G16`）—— 沒有任何東西會擋下來告訴你。
2. **送浮點座標。** 協定的 `x`／`y` 是 `StrictInt`，
   **收到浮點會整則訊息靜默丟棄**。症狀是「別人看不到我動」，而不是錯誤。
3. **在非 `ready` 狀態送。** `FE-R01` 的 `send` 會**拋錯**，
   而那個拋錯發生在 render loop 裡 —— 畫面直接掛掉。

## What Changes

- 新增位置同步：每幀讀本地角色的世界座標，轉成協定的整數像素，
  **最多每 100 毫秒送一次**，而且**只在整數像素真的改變時送**。
- `LocalPlayer` 每幀把權威座標寫進一個**專用的 ref**。
  **不重用相機的跟隨目標** —— 那個 ref 的語意是「相機要看哪裡」，
  之後相機可能鎖定別的東西，兩者會分岔。
- 送出之前 SHALL 確認連線是 `ready`。**不用 try/catch 吞掉錯誤** ——
  吞掉會掩蓋生命週期的 bug。
- 換 scene 時**重置節流與「上次送出的位置」**，並且新連線 `ready` 之後
  可以立刻送第一個位置。

### 不做什麼（Non-goals）

- **不決定頁籤切到背景要怎麼辦。** 那是 `FE-R04`。
  這一刀用 render loop 取樣，背景時 rAF 停 → 自然不送 ——
  **那是「保留決策空間」，不是「已經決定」**：`FE-R04` 之後要斷線或要降頻，
  都還做得到。用 `setInterval` 才會偷偷替它決定「背景繼續送」。
- **不處理自己的回聲。** 「收到自己的 id 就忽略」是 `FE-R05`。
- **不定義多分頁語意。** `FE-R06`（那一列的行為目前未定義）。
- **不碰 `RealtimeClient` 的 `send` 契約。** 它在非 `ready` 拋錯是刻意的。
- **不做插值。** `FE-R08`。

## Capabilities

### New Capabilities
- `position-sync`: 自己的位置什麼時候送出去、送什麼格式、以及什麼時候**不**送。

### Modified Capabilities

（無。`world-player` 的規格只說「位置 SHALL 透過 ref 讀取，MUST NOT 每幀寫入
React state」—— 它沒有描述 `LocalPlayer` 的 props，所以多一個 ref 是實作細節。
「位置要能被網路層讀到」這件事寫在 `position-sync` 自己的 Requirement 裡。）

## Impact

- 新增 `src/realtime/` 底下的同步邏輯與一個 R3F 元件。
- `LocalPlayer` 增加一個 prop（寫入用的 ref）。**內部行為不變。**
- `/world` 的畫面會改變：別人會看到你走動。
- `FE-R04` 之後在這上面決定背景頁籤的策略。
