## 3. 登入之後的守衛

> ⚠️ **這一節原本擋著**，前提是「登入存在，而且 `hello.you` 對同一個人是穩定的」。
>
> **`FE-A01` 做完之後前提成立了 —— 而且是量出來的**（2026-09-10，
> 同一個 browser context 開兩個分頁、各開一條 WS）：
>
> ```
> 分頁1 hello.you = db28e8ce-0c50-4066-9270-3f7a6a5e788e
> 分頁2 hello.you = db28e8ce-0c50-4066-9270-3f7a6a5e788e
> 兩個分頁同一個 id ? true
> 分頁2 snapshot 玩家數 = 1  [{"id":"db28e8ce","name":"分頁測試員","x":0}]
> ```
>
> 協調的鍵有了，而且 snapshot 只有一個玩家 —— 正是規格描述的那個
> 「後端用一個座標歸零的新 `Player` 覆蓋掉舊的」。

- [x] 3.1 `FE-R06-S02`：第二個分頁不連線，顯示提示與「改用這個分頁」（PR #252、#253）

      **兩個設計是被判準逼出來的：**

      - **平手規則**：原本 `holding` 是無條件讓位，而兩個等待中的分頁會在
        同一個時刻到期、同時宣告、然後互相讓位 —— **結果是兩個都沒有資格**。
        改成比 `tabId`、小的贏。對照驗過：拿掉它，`S03` 那條立刻紅。
      - **`taking-over` 跟 `holding` 分成兩則訊息**：我原本合成一則，
        理由寫著「分成兩種只會多一條會漂的路徑」——
        **而那個合併正是平手 bug 的來源**。

      **早退在建立 client 之前，不是在 `connect()` 之前**（規格逐字是
      「MUST NOT 建立 world 連線」）。建了再不連的話 `PositionSync` 會多一次
      莫名其妙的 session 重置。

- [x] 3.2 `FE-R06-S03`：關掉之後接手（PR #253）

      ⚠️⚠️ **端到端第一次跑就紅在這一條，而單元判準是綠的。**
      判準裡的「關掉分頁」是**呼叫 `release()`** —— 那當然會讓出資格。
      真的關掉一個分頁時**沒有人會呼叫它**：React 的 effect cleanup 在關頁時
      不保證跑。修法是自己聽 `pagehide`（不用 `beforeunload` —— 它在
      iOS Safari 與 bfcache 底下不保證觸發，而且會讓頁面失去 bfcache 資格）。

      補的那條單元判準刻意**不呼叫 `release()`**，只發 `pagehide` 事件。

- [x] 3.3 `FE-R06-S04`：跨裝置不在射程內 —— **文件性的**。
      寫在三個地方：規格的第二條 Requirement、`src/realtime/tabLease.ts` 的檔頭
      （「`BroadcastChannel` 只在同源的同一個瀏覽器裡有效」），
