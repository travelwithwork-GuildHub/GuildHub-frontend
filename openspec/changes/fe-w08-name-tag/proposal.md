# `FE-W08` 名字牌：遠端玩家頭上有名字

## Why

⚠️ **這一列是使用者看正式站之後點名的，不是排程排到的。** 2026-09-19 原話：

> 目前多個使用者進去怎麼都長一樣 / 應該要可以長得不一樣 / 有自己的名字 / 有規劃這部分嗎

名字那一半的事實：協定早就送得到（`FE-A01` 實測 snapshot 是 `{"id","name":"名字測試員","av",…}`），
`RemoteIdentity.name` 也存了 —— **但世界從來沒有讀它來畫**。`docs/WBS.md` 的 `FE-W08` 名字牌子列
（3 點）寫的正是這件事：「登入已做，名字送得到；**只剩沒畫**」。它原本排在 `FE-K05` 之後，
而使用者進世界第一眼看到的是「一群一樣的人、沒有名字」—— 這一列提前。

**不做會怎樣**：`CONTEXT.md` 那條鏈「看見 → 靠近 → 旁聽 → 打招呼」的第一環是「看見**誰**」。
沒有名字，Presence 只是一群會動的方塊，`FE-R10`（別人負責）的「兩個瀏覽器互相看得見對方的名字」
那條驗收也永遠跑不了（它明寫依賴這一列的渲染能力）。

## What Changes

- 新 capability `name-tag`：每個遠端玩家頭上一塊 DOM 名字牌，寫協定送來的 `name`；
  跟著角色每幀走（render loop 直接寫 DOM，不進 React，跟門標籤／工位錨點同一條路）；
  畫面外不呈現也不在無障礙樹；空白名字不畫牌子（不顯示替代字）；名字過長截字、牌子寬度固定。
- 自己沒有名字牌 —— 自己的名字在標題列（`IdentityBadge`）。
- 這是第三個「render loop → DOM」的消費者：依 ADR 0010 的「重新考慮」條款，投影用工位錨點同一份 `screenPixelFor`、
  不抽通用元件（考慮過），新 ADR 0012 記這條邊界。

## Non-goals

- **不做 `FE-W08` 的 ProceduralAvatar 那 10 點**（模組化角色、走路動畫）。這一列只做名字牌子列。
- **不畫狀態文字**（`st`）—— 那是 `FE-K05`，它會接上同一塊牌子；這裡只留位置，不留 API。
- **不做牌子之間的避讓**。兩個人站在一起牌子會疊，那是空間的事實；避讓演算法要另外提案。
- **不做「附近」的距離門檻**。相機固定跟著自己（`world-camera`），畫面內就是附近；
  WBS 的「只畫附近／鏡頭內」在這個相機下是同一件事。
- **不做雙瀏覽器互見的驗收** —— 那是 `FE-R10`（別人負責）。這一列給的是渲染能力，
  用偽造的即時後端證明「名單上有名字的人，畫面上就有那個名字」。
- 不改自己的名字怎麼顯示（`IdentityBadge` 不動）。
- 不動 `src/world/OnlineCount.tsx`、`tests/online-count.test.tsx`（別人的 PR 在改）。
