## Why

世界裡的人現在只有名字（`FE-W08` 名字牌）：看得到誰在、看不到他在幹什麼。協定早就有 `status`
（`protocol.py`：客戶端送 `{"t":"status","text"}`，伺服器廣播 `{"t":"status","id","text"}`，`snapshot` 的每個人帶 `st`），
前端也**已經收下來了**（`remotePlayers.ts` 把 `st` 放進名單）—— 但**沒有 UI 送、也沒有畫**（`docs/WBS.md`〈後端 API 前端接了沒〉那一列）。
demo 的閉環是「取名 → 發案 → 看板 → 成軍 → 進房坐位」；狀態文字是這條線上唯一還沒接的即時協定訊息，
接上它，兩個瀏覽器互見的畫面才有「這個人現在怎麼了」這一層（〈demo 之前的核准順序〉#11）。

後端事實（`app/main.py`、`app/realtime/presence.py`）：**12 字上限由伺服器驗，超過就丟棄、不回錯、不廣播**；
廣播送給整個 scene **包含自己**；狀態存在 `PresenceStore` 的 `Player.st`，**每次 `join`（新連線、換場景）都是新的 `Player`，`st` 從空字串開始**
—— 也就是換場景或重連之後，伺服器上的狀態是空的，要自己再送一次。

## What Changes

- 新 capability **`player-status`**：
  - **設定狀態**：世界 HUD 有一個「狀態」控制（已登入才有）—— 幾個快捷狀態、一格自由輸入、一顆清除；上限 **12 字**（`LIMITS.statusText.max`，跟後端 `STATUS_MAX_CHARS` 同源）；超過上限**送不出去**（後端會靜默丟掉，前端不能讓使用者以為送成功了）；送出走目前場景的連線 `{"t":"status","text"}`；連線沒 ready 就不送、有可辨識的回饋；自己目前的狀態在控制上看得到（自己沒有名字牌）；輸入框有焦點時世界鍵盤鎖住（`FE-K04` 同一道 `EditableFocusLock`）。
  - **換場景／重連後重送**：每一條新連線 ready 之後，自己的狀態非空就再送一次（伺服器 `join` 把它清成空）；空的不送。
  - **別人的狀態畫在名字牌上**：名單裡 `st` 非空的人，牌子多一段狀態文字（`snapshot` 的 `st` 與 `status` 訊息都算）；空的沒有；**不改名字牌的幾何**（寬 176、高 28、底邊對錨點 —— `FE-W08` 真瀏覽器的尺不變）；狀態文字變是低頻（可重繪牌子），位置仍每幀由 `RemotePlayer` 直接寫、不經過 React。
  - 真瀏覽器：A 設狀態 → B 頭上看到；A 清除 → 消失；A、B 進房之後 B 仍看到 A 的狀態（重送）。
- **不改契約**：`StatusIn`／`StatusOut`／`LIMITS.statusText` 都已在 `src/api/contract/ws.ts`。

## Non-goals

- **不是 Looking For**（那是 `FE-M10`，要 `BE-G14`，標了 `Later`）—— 這裡是一句自由文字，沒有語意、沒有篩選。
- **不跨重新整理保存**（不用 Web Storage）：伺服器本來就每次 `join` 清空；重新整理之後是空的，跟伺服器一致。
- 不做狀態歷史、不做別人狀態的通知或聲音、不在 3D 角色身上畫（只在名字牌）、不做內容審核。
- 不做自己的名字牌（`FE-R05` 的結構性保證：自己不在名單裡）—— 自己的狀態看控制。
- 不動後端的 12 字規則、不要求後端回錯（給後端的清單裡沒有它，demo 之後再談）。

## Capabilities

### New Capabilities
- `player-status`：設定／清除狀態（12 字、走連線、沒 ready 不送）、換場景與重連後重送、別人的狀態畫在名字牌上、真瀏覽器互見。

### Modified Capabilities
- （無）—— `name-tag` 的既有 Requirement 都不變：狀態是牌子節點裡多出來的一段，牌子的寬高、位置、截字規則照舊。
