## 1. 流程本身（`S07`–`S10`：金鑰要真的被帶走）

- [x] 1.1 剪貼簿的存取包成一個可注入的介面。**注入的是「寫入會成功／會失敗」，
      不是一個 `toHaveBeenCalledWith` 的靶子**（design D4）
- [x] 1.2 首次進入流程的元件：取名字 → 建立身分 → 顯示金鑰 →
      「進入世界」**預設不可用**
- [x] 1.3 兩條放行路徑：複製成功、或明確勾選「我已經自己保存了」
- [x] 1.4 判準：`S07`／`S08`／`S09`／`S10`（8 條）
- [x] 1.5 **突變測試：五個，一個活下來，而它逼出了第八條判準**

      | 突變 | 補強前 | 補強後 |
      |---|---|---|
      | 「進入世界」預設就可用 | 3 紅 | 3 紅 |
      | **不等寫入結果就說已複製** | **全綠 ← 活下來** | **1 紅** |
      | 寫入失敗也顯示成功 | 2 紅 | 2 紅 |
      | 拿掉勾選那條路 | 3 紅 | 3 紅 |
      | 勾了之後取消不收回 | 1 紅 | 1 紅 |

      **活下來的那個為什麼躲得過**：它的**最終狀態跟正確的版本一模一樣**
      —— 失敗時 catch 會把狀態改成 `copy-failed`。中間那一瞬間按鈕是可按的，
      而使用者可以在金鑰**沒有被複製**的情況下進去。
      補的判準用一個**永遠不 settle** 的剪貼簿把那一瞬間停住。

## 2. 兩個入口（`S01`–`S06`）

- [x] 2.1 `/` 從轉址改成正式入口。**`next.config.ts` 那條 307 要拿掉** ——
      它從第一天就是暫時的
- [x] 2.2 `/world` 對訪客顯示可關掉的提示，通往同一個流程
- [x] 2.3 「看過引導了沒有」與「完成首次進入了沒有」**是兩件事**（`S06`）
- [x] 2.4 判準：`S01`–`S06`（11 條）
- [x] 2.5 **突變測試：六個，全部紅**

      | 突變 | 實測 |
      |---|---|
      | 關掉提示就記成完成 | 1 紅 |
      | 提示吃掉指標事件 | 1 紅 |
      | 永遠顯示提示（不看有沒有走完） | 1 紅 |
      | `/` 對已經有身分的人也顯示流程 | 2 紅 |
      | `unknown` 時就顯示流程 | 1 紅 |
      | **`/` 的轉址留著** | 2 紅 |

      最後那個最值得留意：轉址留著的話，新的首頁做好了也**永遠看不到**，
      而**畫面上看不出任何異狀**。`tests/routing.test.tsx` 那條因此改寫成負向的。

- [x] 2.6 **端到端抓到一個單元判準抓不到的 bug**

      在世界裡走完流程之後，標題列仍然顯示「訪客」，要重整才會變。
      `IdentityProvider` 只在掛載時問一次後端，而流程建立的新身分沒有交給它。

      ⚠️ **單元判準抓不到的理由**：`IdentityBadge` 與 `FirstEntryNotice`
      在那些判準裡是**分開掛載**的，各自有一個 provider —— 所以
      「一邊變了另一邊沒變」這件事在那裡**不存在**。補的那條把它們放進
      **同一個** provider，突變（拿掉 `adopt`）紅 1 條。

- [x] 2.7 ⚠️ **修那個 bug 的過程本身值得記**：CI 紅的時候我**先修錯了東西**。
      紅的樣子是「不穩定的測試」（本機綠、CI 紅），所以我先補了等待時機。
      那個修正本身是對的，**但它讓紅燈從偶爾變成每次**，這才露出真正的原因
      —— `adopt(next)` 被突變測試之後的 `git checkout` 抹掉了，
      而 `git checkout <file>` 還原的是 **HEAD**，不是「突變之前」。
      **今天第四次犯同一個錯**，前三次當場發現，這次沒有。
