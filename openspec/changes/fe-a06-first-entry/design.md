# design：`FE-A06 首次進入`

兩輪送 codex `gpt-5.6-sol` 與 Gemini 3.1 Pro。**四個問題，第一輪兩處分歧，
第二輪兩邊都撤回了自己的答案。**

## D1：導流的形狀 —— `/` 強制 ＋ `/world` 可關掉

**第一輪兩邊不一致：**

| | 主張 | 反對對方的理由 |
|---|---|---|
| codex | **軟擋**：`/world` 上一個可關掉的引導層 | 首頁擋「**只照顧從 `/` 進站的人**，首次訪客若由分享連結直接進 `/world`，仍完全碰不到 `FE-A06`」 |
| Gemini | **首頁擋**：`/` 走完流程才進世界 | 軟擋「**防護力太弱**⋯⋯如果改成不能關閉，那就變相成了硬擋，一樣破壞了 `/world` 的可操作性」 |

**硬擋（進 `/world` 直接導向流程）被兩邊同時否掉**，理由一樣：
`FE-A01` 已合併的規格逐字要求「未登入的使用者進入世界時，
世界 SHALL 照常載入並可操作」，而這一項 MUST NOT 讓它變紅。

**第二輪兩邊都接受折衷**：`/` 強制 ＋ `/world` 可關掉，**共用同一個流程**。

codex 的條件是「**同一個流程、兩種呈現**，不能演變成兩套首次進入狀態機」，
並補了一條我沒想到的：

> **關閉 `/world` 引導層不應被記成「已完成首次進入」**，下次仍可再提示。

—— 那條進了規格（`S06`）。把「關掉」記成「完成」的話，
一個手滑點掉引導層的人**再也不會被提示**，而那正是這一項要防的事。

Gemini 的條件是那個訪客降級狀態要真的存在：
「不能讓他們關掉 modal 之後，卻因為缺少 key 而在畫面上看到一堆 `undefined`
或觸發無窮盡的 API 401 錯誤」。`FE-A01` 的四種身分狀態已經處理了這件事。

## D2：角色選擇整段拿掉 —— **兩邊都撤回了自己的答案**

**第一輪又是分歧**：codex 說先做 `FE-A05`（怕 A06 私自實作臨時 UI，
之後重工，還可能提前把未裁決的 `avatar_id` 語意固化）；
Gemini 說 A06 先做一個最小的 N 選 1（怕 A06 被未決的後端問題無限期卡死）。

**第二輪兩邊都改了，而推翻他們的是同一個事實**：

```
src/world/player/ChibiPlayer.tsx:26  const BODY = worldColor('avatarBody')
src/world/player/ChibiPlayer.tsx:27  const LIMB = worldColor('avatarLimb')
```

那是**模組層級的常數**。`ChibiPlayer` 完全沒有 avatar 參數，
而 `av` 這個值雖然有被協定送到、也有進 `RemoteIdentity`，
**沒有任何地方讀它來渲染**。

**世界今天畫不出不同的角色外觀。** 所以做一個角色選擇器的話，
使用者選完之後自己的外觀不變、別人看到的他也不變。

Gemini 的自我推翻逐字：

> 這是一個非常響亮的巴掌⋯⋯前端給使用者選了顏色，進去卻是一坨預設的灰塊
> —— 這對首次體驗的破壞力，**比「不能選顏色」還要嚴重十倍**。
> 這不叫 MVP，**這叫欺騙**。

codex 的：

> 此時做 N 選 1，確實會成為「做出來卻沒用」⋯⋯**這比臨時 UI 的重工問題更嚴重，
> 因為它直接製造錯誤期待。**

**處置：`FE-A06` 只做「拿到一把進入這個世界的鑰匙」，不做外觀。**
角色選擇整段移到 `FE-A05`，而 `FE-A05` 自己還需要一個前置條件 ——
codex 指出的那個**最小可見閉環**：至少讓 `ChibiPlayer` 依 `av` 呈現
可辨識的差異。那不必是完整的 10 點 `FE-W08`，但**在它之前，
任何角色選擇器都是假的**。

⚠️ **這不是砍範圍，是移位。** WBS 上 `FE-A06` 的敘述寫著
「暱稱 → 角色選擇 → 進入 Guild Hall」，這一項把中間那段交給 `FE-A05`，
並在 `governance/` PR 上把兩列的敘述與依賴一起改掉。

## D3：金鑰要「真的被帶走」才放行

兩邊對 Q4（最容易做出來卻沒用的地方）給的是同一件事。Gemini 的描述最具體：

> 急著體驗的陌生人注意力會被巨大的行動呼籲吸走，100% 會直接點擊「進入世界」，
> **連看都不看那串亂碼**。

處置是**加摩擦力**：「進入世界」預設不能按，要嘛複製成功，
要嘛明確勾選「我已經自己保存了」。

⚠️ **兩條路都要有，而且第二條不是裝飾。** 剪貼簿在沒有授權、非安全來源、
或舊瀏覽器上不可用 —— 只留第一條的話，那些人**永遠進不去世界**。

## D4：「複製成功」怎麼驗才不會恆真

**兩邊一致：E2E 一定要真的把剪貼簿讀回來，嚴禁 mock。**

Gemini 逐字：「如果為了圖方便去 mock `writeText` 讓它永遠 resolve，
那這個測試就退化成了無意義的恆真句 —— 你只是在驗證『當我假裝成功時，
UI 確實顯示了成功』」。

**但單元層測不到真的剪貼簿**（jsdom 沒有 `navigator.clipboard`），
而單元層仍然要驗東西。第二輪追問之後兩邊給的答案收斂到同一個形狀：

> **單元層驗的不是「有沒有呼叫剪貼簿」，是「閘門守不守得住」。**

| 情況 | 判準 |
|---|---|
| 寫入 resolve | 「進入世界」**由不能按變成能按**，而且出現複製成功的回饋 |
| 寫入 reject／環境不支援 | 按鈕**維持不能按**，**不得**顯示成功，而且畫面上出現手動保存的路徑 ＋ 勾選框 |

codex 特別指出反向那條為什麼承重：
「一個只在 click handler 裡直接設 `copied = true` 的假實作**會測試失敗**」。

**這跟 `FE-A01` 那條教訓是同一個形狀。** 那次規格特別標示的
「SHALL NOT 送出任何網路請求」單獨拿來當判準是**恆真的**
（`operations.login()` 的 Zod 契約也擋得住），真正承重的是
「使用者得知的是長度不被接受」那一半。

## 測試會連到什麼

- **單元／元件**：不連任何東西。剪貼簿以注入的介面替換 ——
  **注入的是「寫入會成功／會失敗」這件事，不是一個 `toHaveBeenCalledWith` 的靶子**
- **E2E**：本機自己起的後端 ＋ 本機 dev server ＋ 授予剪貼簿權限的 Chromium。
  **MUST NOT 連任何團隊共用位址**

## D5：第二條放行路從「宣稱」換成「持有證明」

**這是封存前送審才改的，而兩個審查者是獨立提出同一個修正的。**

第一版的第二條路是一個「我已經自己保存了」的勾選框。問題：

> 在「妥善保存一串金鑰（高認知負擔與操作成本）」和「打勾以立刻獲得服務
>（極低認知負擔）」之間，急躁的使用者會**毫不猶豫地選擇打勾**。
> 這在心理學上形同提供了一個**合法的捷徑來破壞你們的安全設計**。 —— Gemini

> 它主要證明「使用者**願意解除阻擋**」，不是「**已保存金鑰**」。 —— codex

**兩邊給的處置也一樣**：要他填回金鑰的一小段。codex 說末 6–8 碼、
Gemini 說最後 4 個字元 —— 取中間，而且理由要寫下來：

- **太短**（1–2 碼）猜得到 —— 16 進位的 UUID 尾碼只有 16 個可能，一碼是白給的
- **太長**（整把 36 字元）等於逼人重打，而那會把手抄的人擋在門外

**這條路 MUST NOT 依賴剪貼簿。** 複製成功、手抄在紙上、用手機拍照 ——
只要填得出來，就證明那串字**已經離開這個畫面而且在他手上**。

⚠️ **剪貼簿那條路仍然要留著。** 兩條路各自解決不同的人：
剪貼簿可用的人一鍵完成，不可用的人填最後幾碼。
只留持有證明那條的話，每個人都要手動比對 36 個字元。

⚠️⚠️ **`S12`（填錯不放行）才是這個修正的重點。**
少了它，一個「有填東西就放行」的實作跟原本的勾選框**完全等價**。

## D6：兩個沒有採納的建議，以及為什麼

**codex 建議「下載金鑰檔案」與「系統分享」兩條額外的路。** 沒有做 ——
發表日的現場是筆電，下載一個 `.txt` 之後它躺在下載資料夾裡，
跟「複製到剪貼簿」一樣容易被忘記，而且多兩條路要多兩組判準。
**這一條記在這裡是為了它不被誤讀成「沒想到」。**

**Gemini 指出「關掉引導層只活在這次繪製」對訪客不友善** ——
重整或路由切換都會讓它再彈出來。它建議把「已關閉」寫進 `sessionStorage`。

**沒有改，而理由是規格。** `S06` 逐字要求「訪客關閉了提示，**之後重新進入
世界**，提示 SHALL 再次出現」——而重整就是重新進入。
把它改成一個 session 內安靜的行為，會讓 `S06` 變紅。

**這是一個真的取捨，不是誤解**：現在的行為對「想先逛逛」的訪客比較煩，
換來的是「不會有人因為手滑點掉就再也不被提示」。
要改的話要先改規格，而那要有人決定哪一邊比較重要 —— 記在這裡等那個決定。
