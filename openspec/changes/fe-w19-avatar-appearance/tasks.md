# `FE-W19` tasks

## 1. 映射本身

- [ ] 1.1 在 `src/design/world.ts` 新增兩款 avatar 的顏色組
      （`av=0` 用今天已經在畫面上的那四個 token，`av=1` 是新的一組）
- [ ] 1.2 差異 SHALL 落在主要視覺部位（頭／軀幹／四肢），**不要只換眼睛**
      —— 實測只換眼睛是 3.71%，低於 10% 的門檻（design 的 M1）
- [ ] 1.3 ⚠️ **兩款之間 SHALL NOT 是同色系微調** —— 實測 `#4d5bb0` → `#5f6cc0`
      的差異像素是 **0.00%**（三個通道分別差 18/17/16，全部 `< 32`）
- [ ] 1.4 寫一個純函式把 `av` 換成顏色組。**值域檢查在這裡，不在元件裡**
- [ ] 1.5 值域外一律回 `av=0`。⚠️ **SHALL NOT 取模** —— `999 % 2 = 1` 會讓壞資料
      看起來像使用者真的選了第二款（design 的 D2）

## 2. 本地角色

- [ ] 2.1 `ChibiPlayer` 收一個 `av`，顏色從 1.4 的映射拿
- [ ] 2.2 ⚠️ **SHALL NOT 改 `CHIBI_PARTS` 那四個名字，也 SHALL NOT 改 mesh 結構**
      —— 逐幀動畫靠 `getObjectByName` 查它們，改名字會讓動畫**靜默停止**
- [ ] 2.3 ⚠️ **SHALL NOT 在元件裡寫 `av === 1 ? '#紅' : SKIN`。**
      兩個審查者獨立指出這是最可能做錯的決定

## 3. 遠端角色

- [ ] 3.1 遠端角色元件把名單上那個人的 `av` 傳給 `ChibiPlayer`
- [ ] 3.2 ⚠️ **本地與遠端 SHALL 用同一份映射**（1.4 那個函式），不是各寫一次

## 4. 驗證

- [ ] 4.1 V1 本地：固定相機／光照／姿勢／畫布，`gl.readPixels()` 讀 back buffer，
      `av=0` 與 `av=1` 的差異像素佔角色像素 `≥ 10%`
- [ ] 4.2 ⚠️ **一定要讀 back buffer，不能截圖** —— 畫布沒開 `preserveDrawingBuffer`，
      截圖取到全透明。這個坑在 `FE-A06` 踩過，症狀是「3D 世界一片空白」而產品沒事
- [ ] 4.3 V2 遠端：注入 snapshot 走完整條路徑（snapshot → 名單 → 元件 → 畫面），
      用 4.1 的判準。**不要直接對映射函式斷言**
- [ ] 4.4 V3 值域外：`-1`、`999`、`1.5`、`null` 都畫成 `av=0`
- [ ] 4.5 ⚠️ `999` 那一條要多一句 **SHALL NOT 與 `av=1` 相同** ——
      少了它，取模的實作也會通過
- [ ] 4.6 V4：角色元件的原始碼裡沒有字面色碼

## 5. 突變（驗收條件）

⚠️ **不是「測試全綠」，是「把防禦拿掉，測試要變紅」。**

- [ ] 5.1 元件不再讀 `av` → V1、V2 要紅
- [ ] 5.2 ⚠️ **遠端不傳 `av`（只有本地讀）→ V2 單獨要紅、V1 要仍然綠。**
      這一條證明 V2 不是 V1 的重複
- [ ] 5.3 值域檢查換成 `abs(av) % N` → V3 的 `999` 那一條要紅
- [ ] 5.4 值域檢查整段拿掉 → V3 要紅
      （⚠️ 不會丟例外，three.js 靜默畫成白色，只有像素判準攔得住）
- [ ] 5.5 差異改成只換眼睛 → V1 要紅（3.71% < 10%）
- [ ] 5.6 在元件裡寫死色碼 → V4 要紅
- [ ] 5.7 ⚠️ **把 V1 拿掉、只留 V3** → 一個「永遠畫預設」的實作會全綠。
      這一條是用來確認 `S10` 真的有在守 —— **它證明 V3 單獨存在時是恆真的**
