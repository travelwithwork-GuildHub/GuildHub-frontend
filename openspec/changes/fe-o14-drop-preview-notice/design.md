## Context

`FE-O14`（已封存）在 `WorldCanvas` 上掛了一段 DOM 說明，
在即時層資料來源是 `none` 時告訴訪客這是單人預覽。
它是對的設計 —— 在**當時的用途**下。

當時 `guildhub-frontend.vercel.app` 還沒有給人看。
現在它是這個專案唯一對外的東西，而畫面上只有那段字是文字。

## D1：反轉，不是刪除

**選項 A：刪掉元件、刪掉 `S09`／`S10` 兩條 Scenario。**
最少的 diff。代價是 `S10` 守的規則（不要用同一段文字表示兩個相反的狀態）
從可執行的閘門退回口頭約定。

**選項 B（採用）：把 Requirement 反過來寫。**
「SHALL 呈現說明」→「MUST NOT 呈現說明」，`S10` 的結構原封搬過來。

代價：多了一條「這裡刻意什麼都沒有」的規格，而那種規格容易被讀成
形式主義。**所以理由寫在 Requirement 本體裡**，不是只寫在這裡 ——
design.md 會被 archive，Requirement 不會。

## D2：兩個模型都打回來的第一版

初稿的 `S11`／`S12` 都斷言「畫面上沒有任何 `status` 角色的元素」。
gpt-5.6-terra 與 Gemini 3.1 Pro **各自獨立**指出同一件事：

> Requirement 一面說不禁止呈現真正的連線失敗，一面又規定
> `S12` 禁止所有 `status`。`FE-R12` 用
> `<div role="status">無法連線，請稍後再試</div>` 就會違反 `S12`。

而且它比兩個模型說的更糟 —— **那條斷言今天就是假的**：
`role="status"` 在這個世界已經有兩個使用者，
`WorldCanvas` 的載入中（`world-loading`）與 `InteractionPrompt`。
第一版如果照著寫測試，會在寫的當下就紅，然後被「放寬一點」修掉。

**結論：判準只能下在措辭上，不能下在角色上。** 已寫進 Requirement
的一則 `MUST NOT`，免得下一個人覺得「用角色更嚴」而改回去。

## D3：兩個模型都打回來的第二件事 —— V2 自我矛盾

初稿的驗收條件寫「把 `<SinglePlayerNotice />` 加回 `WorldCanvas`
→ `S11` 與 `S12` 都要紅」。

那是錯的：那個元件第一行就是 `if (realtimeAdapter() !== 'none') return null`。
`S12` 跑在 `guildhub`，元件根本不渲染，**`S12` 會維持綠**。

所以兩條需要**各自的**突變，不是同一個：

| Scenario | 突變 | 為什麼是這個 |
|---|---|---|
| `S11` | 把 `<SinglePlayerNotice />` 加回 `WorldCanvas` | 那正是它要防的迴歸 |
| `S12` | 在 `WorldCanvas` 加一段**無條件**顯示「目前是單人預覽」的元素 | 模擬「`FE-R12` 借用了那段措辭」 |

第二個突變同時也會讓 `S11` 紅 —— 那沒關係，
重點是**存在一個只有 `S12` 抓得到的突變**（第一個突變就是它的反面）。

## D4：正向控制用「載入中已經消失」，不是「容器存在」

兩個模型也都指出「容器存在」太弱：一個內部出錯只剩空殼容器的世界
也有容器，而在空白畫面上「沒有那段文字」恆真。

採用的正向控制是**載入中的狀態不存在**。它比容器強，
因為 `ready` 只有在 `Canvas` 的 `onCreated` 真的跑過之後才會是 `true` ——
空殼容器停在 `ready === false`，`world-loading` 還在，測試會紅。

## 這個判準**證明不了**什麼

誠實寫出來，因為下一個人會需要知道界線在哪：

1. **換同義詞繞得過。** `多人功能暫不可用` 不含那三個詞，測試會綠。
   這是文字斷言的固有極限 —— 退場的 `S09`／`S10` 用 accessible name
   當判準，有完全一樣的極限。**沒有變差，但也沒有變好**
2. **延遲出現繞得過。** 連線關閉 500ms 之後才 `setTimeout` 顯示的提示，
   單次 render 之後立刻斷言抓不到
3. **證明不了訪客覺得畫面乾淨。** 只證明那三個詞不在 DOM 裡

1 與 2 的正確歸屬是 code review 與 `FE-R12` 自己的規格，不是把這條寫得更長。

## 驗證方式

- **V1**：`npm test -- single-player-preview` 全綠
- **V2（驗收條件）**：D3 表格的兩個突變，各自要讓對應的 Scenario 變紅
- **V3**：把 `S11` 的正向斷言（載入中已消失）拿掉、並讓 `WorldCanvas`
  回傳 `null` → `S11` 要仍然綠。**這一條證明 V2 的正向控制是必要的**，
  做完把兩邊都還原
- **V4**：部署後開 `https://guildhub-frontend.vercel.app/world`，
  確認畫面上沒有那段字，而世界還在

測試連到什麼：**不適用 —— 測試不連任何外部服務。**
`WebSocket` 用 `vi.stubGlobal` 換掉，走的是正式碼真正的路徑。
