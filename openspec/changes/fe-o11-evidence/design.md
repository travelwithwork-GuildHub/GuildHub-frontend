# 設計：為什麼是 commit SHA，不是 PR 連結、也不是截圖

## 三個候選

| 候選 | 不可變 | 離線驗得到 | 取得回內容 |
|---|---|---|---|
| PR 號碼／連結 | ✗ 內文可編輯、附件可刪 | ✗ 要連網 | ✗ |
| 截圖進 repo | ✓ | ✓ | ✓ | 
| **commit SHA** | ✓ | ✓ | ✓ `git show` |

截圖也符合前三項，但它**沒有多證明什麼** —— 一張圖片證明不了它是在什麼
版本、什麼環境下拍的，而且會讓 diff 變大、review 變難。commit SHA 反而
把「那次驗證的完整脈絡」都帶著：那個 commit 的 `tasks.md`、`design.md`、
以及當時的程式碼。

## 機器驗得到什麼、驗不到什麼

驗得到：**這個 SHA 存在，而且在 HEAD 的歷史裡。**

驗不到：那個 commit 的內容真的描述了這條 Scenario 的驗證。
**那一格仍然要人讀。** 跟 `commit:` 涵蓋證據同一個強度 ——
機器把「宣告」降級成「指標」，剩下的靠 review。

## 錯誤訊息要分兩種

`missing`（本機沒有這個物件，可能只是淺 clone）跟 `not-ancestor`
（有物件但還沒合併）**不可以混為一談**。講錯會叫人去查一個不存在的問題。
