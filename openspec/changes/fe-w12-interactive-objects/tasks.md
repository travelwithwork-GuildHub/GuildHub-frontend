# FE-W12 互動物件 —— 任務

**規格先合併，再寫產品程式碼。** 每一刀做完要做突變測試：
把那一刀的防禦拿掉，對應的測試 MUST 變紅。

⚠️ **突變測試之前先 commit。** `git checkout <file>` 還原突變的時候會把
未 commit 的實作一起還原掉，而下一條突變會**假紅**（犯過三次）。

## 1. 門的槽位（從走廊矩形推導）

- [ ] 1.1 `src/world/rooms/slots.ts`：`doorSlots(zone)` 回槽位陣列
      —— 容量與間距都從矩形算，**MUST NOT 寫死 -2/0/2/4/6/8**
- [ ] 1.2 `FE-W12-S06`：矩形往東移 → x 跟著移；深度減半 → 容量變小
      —— ⚠️ **不要斷言「每一個座標都變了」**（只改 x 時 z 本來就不該動）
- [ ] 1.3 `FE-W12-S07`：**槽位數目 > 1** ＋ 相鄰間距大於門寬 ＋ 最外側完整在矩形內
      —— 少了「數目 > 1」，容量算成 0 或 1 時「相鄰兩個」是空集合，斷言**空泛為真**
- [ ] 1.4 `FE-W12-S08`：**門數等於容量** ＋ **碰撞盒集合非空** ＋ 視覺包圍盒兩兩不相交
      —— ⚠️ **兩邊都要非空**：只管住門那一側，餵一個沒有牆的場景照樣是綠的
- [ ] 1.5 `LAYOUT` 移除 `door-room-1`／`door-room-2`
- [ ] 1.6 `FE-W12-S25`／`S26`：門的螢幕橫向輪廓 ≥ 角色直徑
      —— ⚠️ 量的是**橫向輪廓**不是投影面積（面積會被高度灌大）
      —— ⚠️ 反向控制：轉成 `turns: 1` 必須紅
- [ ] 1.7 槽位保留的寬度用**門最寬的那個方向**，與朝向無關
      —— 用「沿走廊軸的跨度」的話，`turns: 0` 會算成放得下 19 扇
      —— **同一刀**，不然世界上會同時有寫死的門與生成的門

## 4. 標籤（DOM overlay）

- [ ] 4.1 投影：世界座標 → 螢幕像素。**復用 `framing.ts` 的 `toScreen`**，
      不要再寫一份公式（`FRAMING_ASPECT` 是測試專用，產品用執行期比例）
- [ ] 4.2 `src/world/rooms/DoorLabels.tsx`（DOM，Canvas **外面**）
      ＋ Canvas 裡的投影元件每幀寫 `transform`
      —— **高頻資料不進 React**（`CONTEXT.md`）
- [ ] 4.3 標籤尺寸是**產品常數**，測試從那裡讀，**不得抄一份數字**
- [ ] 4.4 `FE-W12-S09`／`S10`：內容與位置
- [ ] 4.5 `FE-W12-S11`：**標籤數目等於容量且大於一** ＋ 最小支援尺寸下兩兩不相交
      —— 判定是**矩形不相交**（`|dx| ≥ 寬` 或 `|dy| ≥ 高`），不是中心距離
- [ ] 4.6 `FE-W12-S12`：**至少兩扇相鄰的門** ＋ 名稱過長截字，相鄰那個不動
      —— 只有一扇的時候「其他標籤」是空集合，**擠版需要一個受害者才看得出來**
- [ ] 4.7 `FE-W12-S13`：投影落在畫面外時**不在 DOM 裡**
      —— 不能靠「它自己會跑到畫面外」（仍在無障礙樹裡，還可能撐開版面）
