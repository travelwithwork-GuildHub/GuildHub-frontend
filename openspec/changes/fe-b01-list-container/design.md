# `FE-B01` 設計：難逆轉的決定與代價

## D1｜分頁參數：`page`，而且沒有 `limit`

**量到的事實**（讀後端原始碼，不是讀文件）：

```python
# app/api/profiles.py
PAGE_SIZE = 20
async def list_profiles(page: int = 0, _me = Depends(get_current_user)) -> list[ProfileOut]:
    rows = await db.pool().fetch(
        "select * from profiles order by updated_at desc limit $1 offset $2",
        PAGE_SIZE, max(page, 0) * PAGE_SIZE)
```

```python
# app/api/projects.py
async def list_projects(status: ProjectStatus = ProjectStatus.recruiting, page: int = 0, ...):
    "... where status = $1 and expires_at > now() order by updated_at desc limit $2 offset $3"
```

產生出來的型別：`query?: { page?: number }` 與 `query?: { status?: ProjectStatus; page?: number }`。

**代價**：不能用「多抓一筆當作有下一頁的證據」。這是兩個外部審查者第一輪
**都**選為最乾淨的方案，兩邊都在第二輪確認它被推翻。

`docs/WBS.md` 這一列的「offset 翻頁」是錯的敘述，要另開 `governance/` PR 修。

## D2｜下一頁：點下去才探測

三個候選：

| 做法 | 成本 | 會不會騙人 |
|---|---|---|
| `length === 20` 就切頁 | 0 | **會** —— 總數是 20 的倍數時給出空的幽靈頁 |
| 背景預抓下一頁 | **一整頁**（沒有 `limit` 可以只抓一筆） | 不會 |
| 點下去才請求，回空就留在原頁 | 一頁，**只有真的想翻的人才付** | 不會 |

選第三個。被否決的是第二個 —— 只看第一頁就離開的人，那一整頁是純浪費，
而「反正是下一頁的快取」這個論證對他們不成立。

**代價**：最後一次「下一頁」可能點了沒有新內容。
接受它，因為替代方案是替所有人預付一整頁。

## D3｜request identity 的組成，以及它為什麼不叫 `queryKey`

判準綁的是**身分的同一性**：

> 非同步回應只有在其捕捉的 identity 仍等於目前有效的 identity 時，才能提交到畫面。

這一列的 identity 是 `{ 資料種類, page }`。

**刻意不現在建 `status` 的模型。** `FE-B05`（搜尋與篩選）在 W6 且被 `BE-G05` 擋，
這一列畫面上沒有任何東西可以切換 `status` —— 現在把它建進去是替一個
觸發不了的情境預先泛化。

**但也刻意不把程式寫死成「只比較頁碼」。** `FE-B05` 來的時候只要把
`status` 與搜尋條件加進 identity，提交規則與 `S14`／`S15` 都不用重寫。

## D4｜狀態機在這裡，文案在別列

| 東西 | 歸誰 |
|---|---|
| 「現在是哪一種狀態」的判定 | **這一列**（它掌握頁次與回傳筆數） |
| 首次無資料／翻到底／載入失敗的文案與畫面 | `FE-X04`（標著「唯一一份」） |
| 401/403/404/409/422/500 的語彙 | `FE-X03`（標著「唯一一份」） |

三個選項（只留插槽／先寫暫時版之後收編／先做 `FE-X04`）給了兩個審查者，
**兩邊都選只留插槽**。理由是「暫時版」也是第二份，而第二份之後要有人來拔。

**代價**：`FE-X04` 做完之前，這個面板在那三種狀態下由呼叫端給什麼就顯示什麼。
`FE-B04`（人才列表）會是第一個呼叫端，它得自己帶著那三個節點。

## D5｜⚠️ 這一列交代不了「3D 憑什麼存在」

專案硬約束：**「走過去按 E 開面板」= 3D 是一條很貴的導覽列。**
這一列做完之後，看板唯一的 affordance 就是走過去按 E。

第三輪明白要求兩個審查者不准迴避，兩邊都沒有：

> 「`FE-B01` 單獨交代不了。可以把它當作技術能力完成，
> 但不能據此關閉整體產品約束。」

兩邊都認為對的方向是「固定卡槽 ＋ 真實資料摘要，**不假裝知道 total**」——
看板上的卡槽顯示第一頁前幾筆的可辨識摘要，讓沒開面板的人也看得出
「這裡現在有東西／沒東西／暫時讀不到」。

**但兩邊也都判定它不屬於這 8 點**：它要新增世界物件的資料訂閱生命週期、
3D 摘要的版面規則、看板自己的載入／錯誤／空呈現，以及面板與世界的一致性判準。

`docs/WBS.md` 現有的列都不是它（`FE-W13` 是渲染預算、
`FE-W18` 是牆面語意物件的輪廓可讀性、`FE-W12` 已封存）。**要新開一列**，
走 `governance/` PR。

⚠️ **這個缺口沒有寫成 Requirement，而那是刻意的。**
沒有 Scenario 能證明它，而編一條假的正是這份規格自己在禁止的事。
`FE-A05` 在同一個位置踩過：一條「可發現性」的 Requirement 被
`validate --strict` 擋下（每條 Requirement 至少要一個 Scenario），
降級成缺口聲明。

## 待答問題（**量出來之前不寫進 Requirement**）

1. **面板的尺寸與位置。** 它疊在 canvas 上（`layer('panel')` = 20，
   `FE-X01-S06/S07/S14` 已定案），但佔畫面多少、擺在哪一側，
   要在固定的 45° 俯視相機下看過才知道 —— 這個專案已經量過一次
   「看板高 2.3、擺在 z = -6.5，出生點 `z = 1` 時看板的頭在 6.97，超出畫面」。
2. **卡片上放哪些欄位。** `FE-B02`（案件列表，W6）逐字列了六項
   （標題、需求技能、還缺哪些角色、預算範圍、期程、發案者、剩幾天、已幾人應徵），
   `FE-B04`（人才列表，W2）只寫「Talent Card」。這一列不決定卡片內容 ——
   它只決定容器。
3. **「上一頁」要不要做。** 往回走不需要探測（`page > 0` 就確定可行），
   但它會不會被用到，要有真的資料才知道。

## 這一份怎麼驗

- **單元／元件層**：攔在 `src/api/` 那一層，不連任何外部服務。
  `S04`／`S05`（送出的 `page`）、`S07`–`S09`（三種邊界）、
  `S10`／`S11`（失敗不是到底）、`S12`／`S13`（插槽）、
  `S14`／`S15`（延遲回應）都在這一層。
- **端到端**：只打**本機自己起的** dev server，瀏覽器層攔 `/api/*`。
  `S01`／`S02`（按 E 開對的面板）、`S16`–`S18`（Escape 與移動輸入）在這一層。
- **⚠️ 不連任何團隊共用的位址。**

**驗收條件不是「測試全綠」**：每一條防禦拿掉之後要有一條判準變紅。
特別是 `S05`（拿掉就變成「永遠送 page=0」也全綠）、
`S17`（拿掉就變成「開了面板永遠鎖住輸入」也全綠）、
`S15`（拿掉 identity 裡的資料種類，人才流程完全正常，只有切換時才炸）。
