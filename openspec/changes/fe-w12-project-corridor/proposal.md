# `FE-W12` 專案走廊：大廳一扇門 → 傳送進走廊選房，不再一次列出所有房間

## Why

**使用者（demo 前）：主大廳一次把所有 recruiting 專案的門攤在眼前太雜亂、也不像 3D 世界。** 要的是
「大廳只有一扇門 → 按 E 進另一個空間 → 裡面才是那幾扇門、自己走過去選一道進」。

目前 Guild Hall 的走廊（`FE-W11` 的一個分區）直接呈現依 `GET /api/rooms` 生成的 N 扇 Project Door，
出生就全看得到。專案一多，大廳就是一排門與標籤，讀起來像一份清單而不是一個地方。

**不做會怎樣**：這是使用者主動指出的動線病灶。放著不改，demo 時大廳第一眼就是「一排房間清單貼在 3D 上」——
跟 `FE-X17`（HUD 臨場感）一路在修的「像網頁不像 3D」同一種傷害。而**用 DOM 選單解**（曾考慮的方案）會把清單搬回
畫面正中央、刪掉 Project Door 這個空間概念，反而更網頁化。空間動線（走到門、按 E、進另一個空間）才是 3D 該有的解。

## What Changes

- **ADD（`world-interactive-objects`／`FE-W12`）**：
  - 主大廳只呈現**一扇「專案走廊」入口門**，不再直接呈現 N 扇 Project Door。
  - N 扇 Project Door 改渲染在**專案走廊** —— 一塊仍屬於 `lobby` 伺服器場景、但在主大廳視野之外的獨立區域。
  - 對走廊入口門按 `E` ＝ **本地傳送**（覆寫 Rapier 剛體位置＋相機瞬切），**不切場景、不動 WebSocket、不改網址**
    （後端只看到一個位置位移，照常廣播）。走廊入口門本身不要票、不開密碼視窗。
  - 走廊裡對 Project Door 按 `E` 照舊走既有房間門禁進 `room:{id}`；`/api/rooms` 輪詢與成軍／結案 5 秒生命週期
    **完全不變**（人仍在 `lobby`）。從走廊按出口回主大廳（同樣本地傳送）。

## Non-goals

- **不新增後端場景。** 後端 scene 只有 `lobby` 與 `room:{id}`（`_SCENE_ID` regex 鎖死）。走廊是 `lobby` 的視覺分區，
  不是第三個伺服器場景。
- **不做前端「假場景」。** 不建一套跟 server-scene 同名不同義的前端 scene 生命週期（轉場、返回、history、輸入鎖）——
  兩模型一致認定那是陷阱，容易 desync 且與既有 scene 切換邏輯打架。用單純的本地傳送。
- **不做 DOM 選單。** 選房仍是「走到那扇門、按 E」的空間動作，不是彈一個房間清單面板。
- **不改 Project Door 的生成／標籤／進房／輪詢／生命週期邏輯。** 那些（`FE-W12-S01`～`S26`、`FE-V01-S10/S11`、
  `FE-J04-S10`）行為不變，只是發生地點從主大廳的走廊分區換到傳送到達的走廊空間。
- **不改後端、不改 `room-entry-gate` 的門禁語意、不改相機參數（除了傳送當下的瞬切）。**
- **不用 proximity-gate 標籤取代。** 那只是把 N 扇門的標籤晚點顯示，門還在大廳 —— 解不掉「大廳只留一扇門」。
- **不做走廊內部的精緻佈景。** 走廊的地板／牆材質沿用像素風既有 token；華麗佈景不在本 change。
