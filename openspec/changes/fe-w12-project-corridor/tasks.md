# tasks：`FE-W12 專案走廊`

**切法**：每一刀帶著直接證明它的判準。產品碼上限 250 行／刀。動 `src/**/*.tsx` 版面／`src/design/` 前先叫
`ui-ux-pro-max`（動線＋空間，方向已與兩模型談定）。**不動** Project Door 的生成／標籤／進房／輪詢／生命週期邏輯，
只換它們發生的地點（主大廳走廊分區 → 傳送到達的走廊空間）＋加主大廳入口門與本地傳送。

## 1. 走廊空間 ＋ 主大廳單一入口門（`FE-W12-S27`）

- [ ] 1.1 定義走廊空間：一塊仍屬 `lobby`、在主大廳視野外的獨立區域（layout／地板／牆／出生（入口）點）；沿用像素風既有 token，不做華麗佈景。
- [ ] 1.2 主大廳只放**一個**「走廊入口」`Interactable`（不要票、不開密碼視窗）；主大廳不再生成 `door:<project_id>` 門。
- [ ] 1.3 判準：`FE-W12-S27` —— 有 N≥1 專案時，主大廳互動系統只有一個走廊入口、無任何 `door:` 註冊；N 扇門與標籤在走廊、主大廳出生視野看不到。

## 2. 對入口門按 E ＝ 本地傳送（`FE-W12-S28`）

- [ ] 2.1 入口門的 `onInteract`：把 local player 的 **Rapier 剛體位置** `setTranslation` 到走廊入口（不是只改 mesh），相機**瞬切**到走廊入口（不平滑橫越）。
- [ ] 2.2 全程不送 scene 切換、不關/重開 WebSocket、網址維持 `/world`（沿用同一條 `lobby` 連線）。
- [ ] 2.3 判準：`FE-W12-S28` —— E 後剛體座標已設、下一物理步不彈回；相機位置瞬變；無 scene 事件／無 socket 重開／URL 不變。

## 3. 走廊裡的門照舊 ＋ 回大廳（`FE-W12-S29`／`S30`）

- [ ] 3.1 N 扇 Project Door 在走廊生成／標籤／對門按 E 進 `room:{id}`：沿用既有 `world-interactive-objects` 邏輯，只是掛在走廊空間。
- [ ] 3.2 走廊出口互動點：按 E 本地傳送回主大廳入口（同 §2 手法）。
- [ ] 3.3 判準：`FE-W12-S29`（走廊裡對門按 E 走既有門禁；`/api/rooms` 輪詢仍在 lobby；成軍 5 秒內門出現在走廊、結案 5 秒內連標籤與 E 互動一起消失）、`FE-W12-S30`（走廊回大廳）。

## 4. 不破既有判準

- [ ] 4.1 `FE-V01-S03`（房間裡不輪詢、無走廊門）不受影響：走廊屬 lobby，房間仍無這些。
- [ ] 4.2 `FE-J04-S10`（成軍/結案立即重取走廊的門）、project-lifecycle 的 5 秒判準：門在走廊照舊；互動註冊解除確認（看不見的門不能按 E）。
- [ ] 4.3 `FE-W11`（world-layout）不 MODIFY：主大廳移除走廊分區後剩餘分區仍走得到（`FE-W11-S09`）；走廊空間可走性（入口走得到每扇門）另驗。

## 5. 真瀏覽器 e2e

- [ ] 5.1 新片或擴 `scene-switch.mjs`：主大廳走到走廊入口按 E → 量到玩家在走廊、看得到 project 門 → 對門按 E → 進 `room:{id}`（socket `scene=room:{id}`）→ 回大廳。走位沿用 `lib/world.mjs` walker（里程計，不按固定毫秒）。
- [ ] 5.2 傳送不彈回（傳送後量玩家位置在走廊、非大廳）、相機瞬切（位置差反解、非逐幀平移）。
