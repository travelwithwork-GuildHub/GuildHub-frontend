# FE-W06 SpatialInteraction —— 設計

## D1. 互動範圍用距離判定，不用 Rapier sensor

已封存的 `FE-W04` 規格寫著「sensor 是 `Interaction Range` 的原語」。開工前先量了。

```
world.step() 之前查 intersectionPairsWith    → false（假的，narrow phase 沒跑過，不報錯）
step 之後，角色與 sensor 中間隔一道實心牆    → true（牆完全擋不住）
對照：角色朝那道牆走                          → 停在 x=0.54（牆面 0.8 − 半徑 0.25，正確）
```

三個現實：

| | |
|---|---|
| (a) | contract **無論如何都要算距離** —— `FE-V04` 要的是連續的接近度，sensor 只給 boolean |
| (b) | Rapier 的 world 目前是 `LocalPlayer` **私有的**（它自己在 `useEffect` 裡建、存在 ref）。要讓互動物件加 sensor collider，得把所有權搬成共用 provider —— 動已封存項目的架構 |
| (c) | 今天世界裡**一個互動物件都沒有**，內部牆也還沒有（`FE-W10`／`FE-W11`）。遮蔽既沒對象也驗不了 |

加上 (d)：**sensor 根本不解決遮蔽**，所以「用 sensor 比較安全」這個理由不成立。

**選距離。** 代價是非圓形的接近區（例如一張長桌只能從一側靠近）現在做不到 ——
那要等 sensor 或多邊形判定，而今天沒有那種物件。

**跟已封存規格不一致的處理**：兩個模型都說只在這裡記一筆不夠。
所以這個 change 帶一份 `world-physics` 的 MODIFIED delta，把那句話改掉，
並把「step 之前查不到」與「牆擋不住」兩個量測寫進去 ——
不然 `FE-V03`／`FE-V04` 會假設 sensor 幫他們處理了遮蔽。

## D2. 朝向優先於距離

俯視角裡「我面對誰」比「我貼著誰」更能代表意圖：兩個物件並排時，
使用者是靠轉身來選的，不是靠挪半步。

角色的朝向是**離散的 0–3**（`FE-W02` 的協定對映），不是連續角度。
所以「面對的程度」是四個方向向量之一與「角色到物件」單位向量的內積 ——
值域 `[-1, 1]`，站在正對面時是 1。

**背後的物件不硬性排除。** 排除的話，站在兩個物件中間轉身時會出現
「兩邊都沒有目標」的空窗；讓它進分數、由分數輸掉就好。

**代價**：朝向的權重是一個常數（Q3）。權重給太高，貼著 A 卻面向遠處的 B
會選到 B；給太低，轉身就沒有用了。

## D3. 遲滯：決定性不等於不閃爍

平手時用 id 決斷可以保證「同樣的輸入得到同樣的輸出」。
**但那擋不住閃爍** —— 使用者站在邊界上時，位置每幀都在動，
輸入本來就不一樣，於是分數在 `0.4999` 與 `0.5001` 之間來回，目標跟著來回。

所以要**遲滯**：切換目標必須克服一個門檻，新候選要贏現有目標超過某個量。

**門檻的值不寫進規格**（Q1）。Requirement 只寫行為結果：
「只有當另一個候選相對目前目標有明確的優勢時才切換」，
再配一條可驗證的 Scenario（`S04`：微幅來回時切換次數有上界）。

> 這個寫法是 codex 給的：需求寫行為，未知的門檻進 design 的待答問題。
> 兩者都不放棄可驗證性 —— `S04` 拿掉遲滯就會紅。

## D4. 目標改變才通知 React

跟 `RemoteWorld` 同一個模式：每幀算，**只有值真的變了才 `setState`**。

`RemoteWorld` 的 `applyMessage` 回傳一個 boolean 說「名單變了沒有」，
`pos` 一律回 `false`，所以每秒 400 次的位置更新完全不經過 React。
這裡是同一件事：render loop 裡留一個 `previousTargetId`，比對之後才通知。

**遲滯與這道比對是兩層防護，不是重複**：

- 沒有遲滯、只有比對 → 邊界上目標真的每幀在換，比對擋不住，React 照樣每幀重繪
- 有遲滯、沒有比對 → 目標沒變也每幀 `setState`

`S04` 驗前者，`S08` 驗後者。

## D5. 註冊表是一個穩定的 Map，不是 React state

可互動物件用 `useEffect` 註冊／註銷，寫進一個**建立一次就不再換掉**的 Map。

跟 `RemoteWorld` 的 `state.motion` 同一個做法，理由也一樣：
它會被 render loop 每幀讀，而它的身分穩定，所以當 prop 傳下去不造成重繪。

**id 重複要明顯失敗。** 靜默覆蓋的症狀是「有時候按 E 沒反應」，
而那種 bug 從畫面上看不出原因。

## D6. 提示是 DOM

`CONTEXT.md`：**3D 負責空間，DOM 負責產品操作。**

3D 裡的文字在固定的 Orthographic 相機下有可讀性與縮放問題，
而那不是這一層要解決的事。提示要**指名物件**（不是只寫「按 E」）——
兩個物件靠很近時，只寫「按 E」等於沒有回答「按下去會發生什麼」。
