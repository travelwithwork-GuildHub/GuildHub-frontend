**規格先合併，再寫產品程式碼。** 每一刀做完要做突變測試：

⚠️ **突變測試之前先 commit。** `git checkout <file>` 還原突變的時候會把

- [x] 1.7 槽位保留的寬度用**門最寬的那個方向**，與朝向無關

## 突變測試（**十三輪，存活過八條，每一條都補了判準**）

| 刀 | 條數 | 第一輪存活 |
|---|---|---|
| 槽位 | 7 | **4** —— 不對稱補正／容量漏掉 `MIN_GAP`／示意門加回 `LAYOUT`／`MIN_GAP=0` |
| 排序與截斷 | 5 | 0 |
| 輪詢 | 9 | **2** —— 卸載後仍寫狀態／把中止當成失敗 |
| 門與看板 | 8 | **1** —— `key={index}`（**而它是對的**，見下） |
| 標籤投影 | 5 | **1** —— 錨點高度寫死 0 |
| 標籤接線 | 3 | 0 |
| 按 E | 3 | 0 |
| 可走 ≠ 互動得到 | 4 | 1（由另一個檔案的 `S08` 擋） |
| 門的朝向 | 3 | 0 |
| 封存前補的四條 | 5 | **1** —— `key={index}`（同上） |

**存活的那幾條各自的意義**：

- **「示意門加回 `LAYOUT`」**：兩排門座標差一點點，**不相交** ——
  碰撞盒那條判準抓不到。補了「走廊裡不得有寫死的門」。
  ⚠️ **「不相交」不等於「沒有重複」。**
- **「卸載後仍寫狀態」**：React 19 對已卸載的元件 setState 是**靜默的 no-op**，
  那個 `mounted` 旗標是**驗不到的程式碼**。刪掉了，改驗「卸載會中止請求」。
- **「把中止當成失敗」**：**我的假 `listRooms` 忽略 `signal`**，
  中止在測試裡永遠不會 reject。補了一個像真的一樣的假請求。
- **`key={index}`**：**它不會紅是對的。** React 對索引 key 不卸載重建，
  而門今天沒有自己的狀態 —— **沒有假裝有判準守著它**。
