# `FE-X13` 按鈕與表單的最小外觀

## Why

⚠️ **這一列是截圖抓到的，不是規劃出來的。**

使用者傳來 `/login` 的截圖，逐字說「**登入畫面也太醜了 / 輸入匡也看不到**」。
畫面上實際的樣子：

```
GuildHub
取一個名字就可以進去
在世界裡顯示的名字                    □在這台裝置上記住我
不勾的話，這台裝置不會留下任何東西 —— 換裝置或清掉資料就要靠恢復金鑰回來。
進入世界

已經有身分了？
貼上你的恢復金鑰                      用金鑰回來
```

「進入世界」與「用金鑰回來」是**兩行漂著的字**，不是按鈕的樣子；
而每一個輸入框都是**隱形的**。原因是 Tailwind 的 preflight 把 `<button>`
與 `<input>` 的預設外觀清光了，而沒有任何一行樣式加回去。

**18 條端到端斷言全綠，而那個 CTA 沒有人會認得出來。**
⚠️ **這跟 `FE-W12`「門看不出來是門」是同一種形狀** —— 那次是走廊上的六扇門
在畫面上只有 10 像素的細縫，444 條測試沒有一條抓得到。

`FE-A06`（首次進入）已經替它自己的流程補了最小可用的外觀，但那三個常數
（`PRIMARY`／`SECONDARY`／`CHECK_ROW`）**寫在 `FirstEntryFlow.tsx` 裡，
而且沒有任何判準守著它們** —— 有人把 `className` 刪掉，18 條端到端斷言全綠。

`/login`（`FE-A01`，已封存）連那份最小外觀都還沒有。

## ⚠️ WBS 的敘述漏了一半

`docs/WBS.md` 上這一列只說了**按鈕**。使用者的原話包含「**輸入匡也看不到**」，
而兩個外部審查者都獨立認為輸入框在這一列的範圍內（理由見 design 的 `D3`）。

**這份 proposal 涵蓋按鈕與輸入框兩者。**
`docs/WBS.md` 的敘述要補，但那要另一個 `governance/` PR ——
這裡先把缺口寫出來，不要讓它靜默消失。

## What Changes

- 一句 Requirement 說「可以按的東西看得出來可以按、可以輸入的地方看得出來可以輸入」，
  並且**給得出一個量得到的門檻**
- 把 `FE-A06` 那份最小外觀收成共用的東西，套到 `/login`
- 新增**一個**語意 token 給控制項的邊界用
- 加上判準：在真的瀏覽器上量 `getComputedStyle()`，
  **驗收條件是「把 `className` 拿掉要變紅」**

## ⚠️ 不做什麼

兩個外部審查者被獨立問到「這一列最可能做錯的決定是什麼」，
**答案完全一致**，所以逐條寫進範圍限制：

- **SHALL NOT 建立 `<Button>` / `<Input>` 元件庫**（帶 API、狀態與變體的那種）。
  那是 `FE-X05`（完整的表單一致性，W2，未開始）。
- **SHALL NOT 順手統一欄位尺寸、間距、錯誤狀態、focus、disabled 或
  responsive layout。** 同上。
- **SHALL NOT 改 `--color-line`。** 它同時用在分隔線與卡片邊界上，
  而那些**不需要**達到控制項的對比門檻；改它會讓整個介面變重。
- **SHALL NOT 把色碼、Tailwind class 名稱或 padding 寫進判準。**
  那會把目前的臨時外觀變成**沒有經過規格決定的永久契約** ——
  而這個專案犯過這個錯。

## Impact

- 新增 `openspec/specs/control-affordance/`
- `src/app/globals.css`：新增一個語意 token
- `src/first-entry/FirstEntryFlow.tsx`：三個常數搬到共用位置
- `/login` 的畫面：套上同一份外觀
- 新增判準（真瀏覽器，量 `getComputedStyle()`）
