## ADDED Requirements

### Requirement: 匿名的多分頁是合法的，登入之後不是

**匿名連線的每一條都是一個不同的人。** 後端 `_identify()` 在沒有 session 時
回 `str(uuid.uuid4())`，所以兩個匿名分頁在世界裡就是兩個訪客。

系統 MUST NOT 阻擋匿名的多分頁。它不只合法，而且是**本機驗證多人行為的手段** ——
瀏覽器 E2E 就是靠兩個分頁互相看見對方。

**登入之後不一樣。** 兩個分頁共用同一張 session cookie，
所以 `hello.you` 是同一個 `user_id`，而後端的 presence 是以 `user_id` 為鍵的
單一 `Player`。實測（自己簽一張 session cookie 重現）：

```
分頁1 連上，走到 x=320
分頁2 連上
  → 兩個分頁的 hello.you 是同一個 id
  → 分頁2 的 snapshot 裡，那個共用 Player 的 x = 0     ← 分頁1 被瞬移回原點
  → 分頁1 收到一則 presence.join，裡面是它自己的 id
```

根因在後端：`presence.join()` 是 `self._players[user_id] = Player(...)`，
用一個座標歸零的新 `Player` 覆蓋掉舊的。

#### Scenario: [FE-R06-S01] 匿名的兩個分頁互相看得見，不得互相阻擋

- **WHEN** 同一台機器、同一個瀏覽器開兩個匿名分頁進同一個 scene
- **THEN** 兩個分頁都連得上
- **AND** 每個分頁在對方的名單裡各是一個獨立的人

#### Scenario: [FE-R06-S02] 登入之後，第二個分頁不連線

- **WHEN** 已經有一個分頁以某個 `user_id` 連著 world
- **AND** 同一個瀏覽器用同一個身分再開一個分頁
- **THEN** 第二個分頁 **MUST NOT 建立 world 連線**
- **AND** 它顯示「你已經在另一個分頁裡開著這個世界」，並提供一個「改用這個分頁」的動作
- **AND** 第一個分頁的角色**沒有被瞬移回原點**

#### Scenario: [FE-R06-S03] 第一個分頁關掉之後，第二個分頁可以接手

- **WHEN** 第二個分頁因為上一條而沒有連線
- **AND** 第一個分頁被關閉
- **THEN** 第二個分頁在合理時間內取得資格並連線
- **AND** 中間**不得**出現兩條同身分的連線同時存在

### Requirement: 守衛是止血，根治在後端

前端的跨分頁協調 SHALL 被記錄為**暫時的止血措施**，MUST NOT 被當成問題已經解決。

它擋不住的情況至少有三種：分頁崩潰（沒有機會釋放資格）、
兩個分頁在同一瞬間搶資格的競態、以及不同瀏覽器或不同裝置用同一個帳號登入 ——
**最後那一種前端完全沒有辦法**，因為協調只在同源的同一個瀏覽器裡有效。

根治要後端做兩件事：`presence.join()` 對既有的 `user_id` 不得重建 `Player`；
以及**把連線數與玩家狀態分開**（`disconnect` 已經有 `still_here` 檢查，
`join` 沒有對應的那一半）。

#### Scenario: [FE-R06-S04] 跨裝置的同一個帳號不在守衛的射程內

- **WHEN** 同一個帳號在兩台不同的裝置上登入同一個 scene
- **THEN** 前端的跨分頁協調**不會**、也**不該**阻擋它
- **AND** 位置互相覆寫的問題仍然存在 —— 這是後端的責任，不是這一層的
