## Why

後端 `c6f3928` 已經上線（Caddy 同源閘道），production 的資料層與即時層都切到 `guildhub`
（`fe-o14-rest-build-gate`，2026-09-17）。從這一天起，「前端有自己的後端、功能先做完再銜接」
這個前提**反過來了**：真後端在前面，本地替身（`internal`）在後面。

2026-09-17 對本機自起的 c6f3928 跑了一輪既有的契約套件與一輪人工探測，量到的事實
（全部只打 127.0.0.1）：

- 契約套件 `guildhub` 目標：49 過、3 skip（房間人數，設計如此）、**11 todo** ——
  todo 全是「到不了的欄位」（`title`／`body`／`needed_skills`／`seat_count`），
  因為 **`internal` 沒有 `POST /api/projects`、`form-team`、`close`、`seats`**，
  而契約套件的規則是同一份測試對兩個目標各跑一次、測試檔裡不准有目標分支
  （`FE-O05` 的 S02）。這六個操作的行為今天**沒有任何測試釘住**。
- 真後端在這六個操作上有幾條**前端規格必須照著寫、而文件沒有講**的行為：
  建案完全不驗欄位（空 `title`、`seat_count` 0 或 9 都 201）；`GET /api/projects`
  預設只回 `recruiting`；`form-team` 可以重複呼叫（換密碼、舊密碼立即失效），
  **對 `closed` 的專案再呼叫也 200、案子復活**；`seats` 的兩種 409 只靠 `detail`
  文字區分；超出 `seat_count` 是 400 不是 409；`close` 冪等、座位整批刪，
  **但結案後舊的 room token 仍能列座位、坐位（201）**；後端優雅關閉時
  客戶端收 close 1012。

不做會怎樣：`FE-J01`／`FE-B02`／`FE-B03`／`FE-J04`／`FE-J13`／`FE-R12` 六份規格
接下來兩週要開，每一份都會對這些行為做假設。假設寫錯的代價在 `FE-N08` 付過一次
（規格以為未成軍是 403，真後端是 404）。而且**這些行為會變** —— 後端修掉任何一條
（例如開始驗 `seat_count`），前端不會有任何東西變紅；`FE-O07` 想要的漂移偵測今天
只涵蓋 `internal` 也有的操作。

## What Changes

- 新 capability **`switch-rehearsal`**：一個可重跑的演練套件（`tests/rehearsal/`），
  由既有的 `scripts/contract-guildhub.mjs` 用同一套 preflight／起停邏輯（loopback、
  port 沒人、可拋棄庫）起真後端後執行；走一次完整閉環（登入 → 建案 → 列表／詳情 →
  成軍 → 門 → 進房 → 座位 → 私訊 → 結案），並把上面量到的 REST 行為釘成**觀測基線**
  （後端改了任何一條，演練要紅 —— 紅的意思是「觀測值變了、要重新分類」，不是 regression）。
  基線分兩種：前端要相容的 `contract`，與送回後端裁定的 `anomaly`（建案不驗欄位、closed 可復活、
  結案後舊 token 仍能坐位）；`anomaly` 不得被任何功能規格當成可以開放給使用者的行為。
- 每次演練 SHALL 產一份報告到 `docs/evidence/fe-o08/`（後端 commit、每一步的結果、
  紅的步驟、要送回後端的清單）；報告由機器從 vitest 的 JSON 產出，人不手寫。
- `docs/evidence/fe-o08/README.md` 記這一輪的差異清單與決策（哪些條目送回後端、
  前端各自在哪一份規格接手）。README 列的每一條 SHALL 對得回期望表的一個項目
  （測試比對），不然兩份會漂。
- 演練**不**放進契約套件（那裡禁目標分支、CI 只跑 `internal`）；它只在本機、
  只對自起的後端跑，跟契約套件的 `guildhub` 那一輪同一條路。

## Non-goals

- **不替 `internal` 補這六個操作。** 那是 `FE-O03` 常態列「產品操作隨各能力追加」的事，
  點數算在 `FE-J01`／`FE-J04`／`FE-J13` 裡（design D4）。這一份只把「它們今天不在」
  記成事實。
- **不修後端、不改契約（`schema.d.ts`）。** 量到的行為是期望不是 bug 判定；
  哪些要請後端改，列在 README 的〈送回後端〉，由後端決定。
- **不做 `FE-O08` 原本第二列的「部分銜接」**（已對齊的走真後端、沒對齊的走本地）——
  production 已經全程 `guildhub`，那一列的前提不存在了；WBS 那一列另由 `governance/` 處理。
- 不用瀏覽器跑演練。閉環的六個操作今天沒有 UI；瀏覽器層的驗收屬於各功能的 e2e。
- **不釘 WebSocket 的關閉碼（SIGTERM → 1012）。** 演練是 REST 閉環；關閉碼是 `FE-R12` 斷線復原的規格要釘的東西，
  這裡只把量到的數字記進 README〈量到但不在基線裡〉。
- 不對「基準」以外的後端 SHA 承諾綠燈。基準是 `c6f3928`；對別的 SHA 跑，紅的條目就是漂移，報告會標出後端 SHA。
