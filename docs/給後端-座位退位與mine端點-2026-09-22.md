# 給後端：座位退位 ＋ `?mine=true` 落地確認（2026-09-22）

前端看過 BE-G38（`GET /api/rooms?mine=true`）與整合指南 §5.6，對照昨天討論的
「坐了之後要可以再站起來」。下面分成 **① 需要後端調整的**、**② 我們自己做、不用你動**、
**③ 我們刻意不請你做（省你時間）**。

---

## ① 需要後端調整：一個最小的「退位」端點 🔴

### 為什麼

昨天說的「坐了之後要可以再站起來」，拆開來是兩件事：

- **物理上站起來走開** —— 這個**前端已經可以了**：入座只是把角色搬到工位一次，之後 WASD 直接走，
  沒有任何鎖。這不需要你動。
- **真正把座位空出來（那一格恢復可坐、自己可以改坐別格、別人也能坐）** —— 這個**做不到**，
  因為整合指南 §5.4 寫著「**沒有釋放座位的端點（已於 WBS v0.2 砍除），座位只在結案時全數清空**」。

現在的實際體感是**最糟的中間狀態**：demo 現場，一個人從工位站起來走掉了，
但那一格在畫面上**永遠顯示他還坐著**、別人點不了、他自己也不能改坐別格（`already_seated` 409）——
看起來就像壞了。這正是昨天要解的「位置的問題」。

### 想請你加的（範圍愈小愈好）

```
DELETE /api/projects/{project_id}/seats
  → 刪除「目前登入者」在這個 project 的那一格座位
  → 200（或 204）；沒有座位時也回成功（冪等，no-op）
```

- **只刪自己的座位**（從 session / room token 認得出是誰），不吃 body、不指定 `seat_index`。
- **冪等**：重複 DELETE、或本來就沒坐，都回成功，不要 4xx。
- 我們**不需要「換位」端點**：改坐別格＝前端先 `DELETE` 退位、再 `POST` 入座，兩步就夠。

### 幾個想跟你確認的契約細節（codex 一起看過）

1. 退位是否**原子**？（和入座一樣靠唯一鍵，避免兩人同時搶同一格的競態）
2. 退位後 `GET /api/rooms?mine=true` **是否仍列這間房**？——「坐過」是歷史條件，
   我們希望**仍列**（他退位了但還是「所屬」），不要因為「目前沒座位」就從 `mine` 消失。
3. **已結案（`closed`）**時 DELETE 的回應／錯誤碼，和入座那組保持一致，讓前端能收斂畫面。
4. 座位查詢（`GET .../seats`）**不要被快取**到超過我們的輪詢週期（見 ③）。

### 如果你們決定不加

那也請明講，我們就把 demo 規則**寫死並在畫面上標清楚**：「每個專案只能選一次座位，
到結案前不可更換」——至少不會是「人走了、座位卡住」那種看起來壞掉的樣子。
但我們的建議是：這一顆退位端點成本很小、直接解掉 demo 最明顯的怪異，值得加。

## ② 我們自己做、不用你動

### `GET /api/rooms?mine=true`（BE-G38）—— 收到，會這樣接

- 跑 `pnpm contract:generate` 重生 OpenAPI 型別，拿到 `mine` 參數。
- 單一入口的「我的房間」清單用 `?mine=true` 排最上面；**其餘的門仍用不帶參數的 `GET /api/rooms`**，
  並**保留「其他房間（輸入密碼）」入口** —— 我們理解「只進房沒坐下不算 `mine`」，
  新成員第一次一定進不了自己的 `mine` 清單，所以密碼入口不能拿掉。
- 已結案不列、最多 12、新到舊、需登入 —— 都照你寫的。

### 座位兩種 409 改讀 `code`

前端目前是用中文 `detail` 字串分 `seat_taken` / `already_seated`（我們之前請你加 `code`，
整合指南 §4 看到 `seat_taken`、`already_seated` 兩個 code **已經有了**）。
我們會把前端從「比對 `detail` 文字」改成「讀 `code`」——這是我們自己的事，不用你動。

## ③ 我們刻意不請你做（省你時間，除非 demo 劇本改變）

- **WebSocket 座位事件**：協定目前只有 `move` / `status` / `chat` / `pos`，座位變化靠 30 秒 REST 輪詢。
  退位後別人最慢 30 秒才看到那格空出來 —— 不即時，但**不影響正確性**。我們會在使用者
  「重新聚焦視窗 / 按下入座 / 手動刷新」時立即重拉座位，把體感延遲壓下去。
  demo 三天內**不值得為此擴協定**（廣播、重連補償、測試面都會變大）。
  除非 demo 劇本要演「多人即時搶同一工位的交接」，才另談。
- **換位端點**：如上，退位＋重坐就夠，不用另做。

## 一句話

**唯一想請你加的是一顆最小的退位端點 `DELETE /api/projects/{project_id}/seats`（只刪自己、冪等）**，
解掉「站起來走了、座位卻卡住」這個 demo 最明顯的怪異；其餘（`mine` 接線、409 改讀 code）我們自己做，
WS 座位事件和換位端點 demo 不用做。
