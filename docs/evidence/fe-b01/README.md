# FE-B01 的瀏覽器證據

`node tests/e2e/board-panel.mjs`（需要 `npm run dev`）產生的。

## ⚠️ 這些截圖證明什麼、不證明什麼

**證明**：走到看板前按 E 開得出對應的面板（`S01`／`S02`）；面板開著時按方向鍵
WebGL 畫面的穩定差異不到對照組的 1%（`S18`）；Escape 之後面板消失、再按方向鍵
畫面差了十幾萬個像素（`S16`／`S17`）。移動的尺是 WebGL 像素，不是 DOM。

**不證明**：真的 GuildHub 後端整合可用，也**不**證明線上的 Vercel 站可用。
回應是腳本自己攔截並偽造的（`page.route`）。**不連任何團隊共用的位址。**

## 這次跑出來的數字（2026-09-11）

```
還沒開面板時按方向鍵，畫面差了 231378 個像素（人在走）
[S01] 專案看板開的是案件清單
[S18] 面板開著時按方向鍵，畫面只差 16 個像素（上限 2314，人沒有走）
[S16] Escape 關掉了面板
[S17] 關掉面板之後按方向鍵，畫面差了 164029 個像素（下限 46276，人走得動）
[S02] 人才看板開的是人才清單
```

閾值是**相對於對照組**的（鎖住 ≤ 1%、放開 ≥ 20%），不是絕對值。第一次跑鎖住是 0 個像素，
第二次是 16 個 —— swiftshader 的雜訊本來就不是 0，`=== 0` 會是一顆 CI 未爆彈（兩個外部審查者都指出）。

## 看過畫面之後的兩個備註（`design.md` 待答問題 1）

- 面板佔右側 `min(26rem, 100vw − 2rem)`、上下各留一個 gutter。1280×720 下看板與角色仍在畫面裡，沒有被蓋住。
- 焦點落在列表上時是瀏覽器預設的 focus ring。看得見是對的（`FE-X13`），長什麼樣交給 `FE-X05`。
